# GameForge — Source Hardening Pass (2026-11-07)

Scope: the uploaded `GameForge_SourceCode.zip` (2,605 files, ~84k lines of Python plus C++/config/docs).
Environment: Linux sandbox, Python 3.12, PySide6 6.12 (offscreen). **No Windows, no Unreal Engine, no Ollama.**
This pass fixes the defects it could find and prove. It is not a guarantee of zero bugs: engine builds,
packaging, live editor ops and model behaviour can only be verified on the Windows host.

# Round 2: agent pipeline, LLM calling, frontend (2026-11-07, later)

## 6. Agent and game-creation pipeline

| Area | Before | After |
|------|--------|-------|
| **Fabricated success (critical)** | When `create_game` failed, `runtime.py` recorded a made-up repair ("// Automatic repair applied", `result_status="SUCCESS"`, diagnostics 1→0), set the outcome to SUCCESS and told the user "Game creation complete and verified! All 11 Forge stages and QA scenarios verified PASS." | Failures are reported as failures: failed stage, error text, root-cause category, per-stage status table, project directory and resumable run id. The task ends `FAILED`, and the plan is marked `failed` (new `PlanArtifactStatus` value). |
| Success message | Read `package_exe`, a key `create_game` never returns, so it always showed `Packaged/Windows`. | Uses `exe` and `report_path` from the outcome and lists every stage's status. "Not found on disk" is stated when there is no exe. |
| Live progress | `_stage_event_forwarder` discarded every stage event, so the chat was silent for the whole multi-minute build. | Stage events go through a thread-safe queue and are streamed as `RUNNING` status events (stage, message, timing, errors). The chat renders them as a live progress item. |
| Crash handling | An exception in the build path was logged and execution fell through into the generic LLM loop, which then improvised an answer. | It is reported as an error event and the task ends `FAILED`. |
| Cancel during a build | `create_game` checked `cancel_event` only once, before the run started. | A watcher thread forwards a cancel to `ForgeExecutor.request_cancel()` during the run, and the chat reports that the run is saved and resumable. |
| GDS drafting | `prompt_to_gds` ran on the event loop thread and its errors were silently swallowed. | It runs via `asyncio.to_thread`, failures are logged, and a "Drafting the game design spec" progress item is shown. |
| Scratch-genre GDS | One model attempt, then deterministic fallback. | One repair round-trip with the validation errors (same policy as the template path) before the fallback. |
| LLM plans | 12 s timeout, so a local 9B model almost always fell back to the template plan. Hallucinated tool names were accepted. | 90 s default (`GAMEFORGE_PLAN_TIMEOUT_S` overrides it). Step tools are filtered to the gateway's real tools; at most 20 steps; non-object steps are skipped; an empty plan falls back. |

## 7. LLM calling (`OllamaProvider`)

- **Streaming is non-blocking and cancellable.** The HTTP read runs on a worker thread that feeds an `asyncio.Queue`. Closing the generator, or setting `cancel_event`, closes the connection, which makes Ollama stop generating.
- **Stop now reaches the model.** Desktop `AgentWorker.stop()` calls `runtime.cancel_task()`. The runtime keeps a thread-safe `threading.Event` per session, passes it to `stream_chat`, checks it on every chunk, and refuses to act on a half-finished answer, so no partial heredocs are written to disk.
- **Native tool calls are cancellable.** `chat_with_tools` is awaited through `_await_cancellable`, which returns as soon as the user cancels instead of waiting out the 180 s timeout.
- **Sticky, bucketed `num_ctx`.** Each caller used to pick its own value (8192 for design, 32768 for chat), which forced Ollama to reload the model between calls. The provider now reuses the largest bucket already used per model, so the context only grows, and an explicit larger request is still honoured.
- **Context overflow is visible.** A warning is logged when the prompt plus output exceeds `num_ctx`, where Ollama would otherwise silently drop the oldest context, including the system prompt. Streaming now budgets `num_ctx` from the real input size instead of always using the model maximum.
- **No timeout retries.** A read timeout is no longer retried 3 times (up to 9 minutes); only connection and 5xx errors are retried.
- **`/api/tags` cache.** Availability and model-list probes share one request, cached for 5 s per host, because the UI calls them several times at startup and on every dropdown open.
- **Host normalisation.** `http://host:port/` is accepted, matching how `OLLAMA_HOST` is commonly set.
- **Offline model list.** `ModelRouter.list_all_models()` returns the configured routing models, labelled "provider offline", instead of an empty dropdown.

## 8. Frontend

- **Chat streaming render throttled to 50 ms.** Every token used to re-run markdown→HTML→layout for the whole message, which was O(n²) per reply and caused the "UI STALL" warnings. `finalise()` always flushes the last render.
- **Markdown renderer.** Adds italics and ~~strikethrough~~, applies inline formatting inside headings, and makes only `http(s)`/`mailto` links clickable (model text is untrusted).
- **Live progress item.** The chat renders `RUNNING` status as a live item ("🏗️ Build Editor: Running build editor…", "⚠️ … failed (3.0s)").

## 9. Other

- `scripts/models/gen_routing.py` no longer overwrites the shipped `model_routing.json` when imported by tests; writing requires `write=True`, which the CLI passes. Note that its role assignments are fixed policy, not derived from the eval reports it lists.
- Architecture §8 install budget set to ≤ 400 MB (owner decision), matching `build_standalone.MAX_PACKAGE_SIZE_MB`.

## 12. Round 3 (final): routing, honesty, hosted cancel

- **Model-assisted intent routing** (`backend/agent/intent_classifier.py`). The runtime asks the already-loaded chat model for a structured classification: `chat`, `code_change`, `create_game`, `modify_game` or `project_query`. It uses a JSON-schema output with `think: false`, an enum-validated intent and a confidence score.
  - The model's answer is used only when its confidence is at least 0.6.
  - Otherwise the existing keyword heuristics decide, so behaviour without Ollama is unchanged.
  - Results are cached per prompt, the default timeout is 15 s (`GAMEFORGE_INTENT_TIMEOUT_S`), and `GAMEFORGE_DISABLE_LLM_ROUTING=1` turns the feature off.
  - The classification drives both the conversational short-circuit and `_is_game_creation_request`. Tests: `test_intent_classifier.py`.
- **Truthful routing metadata.** `model_routing.json` and `gen_routing.py` now say the roles are a fixed policy and that the P9 eval reports are listed for reference only. Previously they claimed the reports generated the assignments.
- **Hosted providers honour cancel.** `_iterate_in_thread` stops when `cancel_event` is set or when the consumer stops reading, and it closes the SSE generator, which drops the upstream request instead of letting it stream (and bill) in the background.

## 13. Known weaknesses still open

- The keyword heuristics remain the fallback whenever the model is offline or unsure, so misrouting can still happen in that case.

- Everything was verified in a Linux sandbox. Windows, UE 5.7.4 packaging and live Ollama behaviour still need the host acceptance run described in `context.md` §4.
