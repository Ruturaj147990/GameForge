# Research Findings and Their Consequences — 2026-10-31

**Author:** Claude (Opus 5.5). Each finding gives its source, how much to trust it, and the design consequence for
GameForge. Wherever possible, findings that drive a decision were confirmed against the local UE 5.7.4 install on
disk (marked **[disk]**). Third-party blogs are marked *(secondary)* and are never the only basis for a decision.

---

## 1. Unreal Engine: where the engine is going

| # | Finding | Source / trust | Consequence |
|---|---|---|---|
| R1 | UE 5.7 shipped on 12 Nov 2025. **PCG is production-ready.** Substrate (modular materials) shipped, MegaLights is Beta and Nanite Foliage is Experimental. 5.7 also includes an in-editor AI Assistant (Epic cloud). | Epic 5.7 release posts; [disk] `Plugins/Experimental/AIAssistant` present | Keep PCG as the world backbone (already PASS). Do not depend on Epic's cloud assistant: it needs an Epic login and sends data off the machine. |
| R2 | **UE 5.8 ships an experimental "Unreal MCP" plugin** (`ModelContextProtocol`, `ModelContextProtocolEngine`, `ModelContextProtocolEditor`). It speaks HTTP+SSE at `http://127.0.0.1:8000/mcp`. Tools are declared through the **Toolset Registry**: Python classes derive from `unreal.ToolsetDefinition` with `@toolset_registry.tool_call`, and C++ uses `UToolsetDefinition` with `UFUNCTION(meta=(AICallable))`. **It has no authentication layer**, and tool calls run serially on the game thread. | Epic docs "Unreal MCP in Unreal Editor" (primary). A dissenting secondary source (mythiclemon) reads the 5.8 binaries differently. [disk] 5.7.4 has neither plugin. | **AD-16:** stay pinned to 5.7.4 for the roadmap. Design GameForge's C++ op libraries so a 5.8 build can add `meta=(AICallable)` and publish the same functions as MCP tools ("dual publish"). Unreal MCP may be used **only for read-only ops**, because it has no auth. Mutations keep the token-authenticated link. **Move the GameForge bridge off port 8000** (collision, audit F-08). |
| R3 | **MetaHuman 5.7: a Python/Blueprint API** can create, sculpt, conform, dress, rig, texture, assemble and export MetaHuman Character assets, in batch or in the editor. | metahuman.com 5.7 release; Epic docs (the page lists 5.8 as a prerequisite, a conflict noted). [disk] `Plugins/MetaHuman/MetaHumanCharacter`; `UMetaHumanCharacterEditorSubsystem` has 28 BlueprintCallable functions incl. `BuildMetaHuman`, `RequestAutoRigging`, `RequestTextureSources`, `SpawnMetaHumanActor` | A high-quality character backend is scriptable on this engine. `RequestAutoRigging` and `RequestTextureSources` call Epic cloud services, so they need user consent and an Epic login and must be marked egress. It becomes an optional backend in P7 behind approval. The procedural humanoid stays the offline default. |
| R4 | **Game Animation Sample Project (GASP)** was updated for 5.7 with 400 new animations. It uses Motion Matching and Choosers (Pose Search column), adds a Foot Placement Control Rig node, and uses the Mover plugin (still Experimental). | Epic tech blog, 3 Dec 2025 (primary) | Locomotion quality: P7 imports GASP animations **when the user has added the sample from Fab**. They are Epic content usable in Unreal projects; record the licence class `EPIC_CONTENT`. Use Motion Matching (PoseSearch, [disk]) on **CharacterMovementComponent**, not Mover. |
| R5 | **Mover is still Experimental in 5.7**. Epic will keep supporting CharacterMovementComponent "for the foreseeable future". StateTree has been production-ready since 5.5/5.6 *(secondary)*. | Epic Mover docs (primary); Stray Spark *(secondary)* | Kit characters use **CMC**. Kit AI keeps its native C++ state machines, which are tested, and adds StateTree only where designers need an editable asset. |
| R6 | **Enhanced Input injection:** `InjectInputForAction(Action, RawValue, Modifiers, Triggers)` and `Start/StopContinuousInputInjectionForAction` run triggers and modifiers "as if the input had come through the underlying input system". Engine test plugins `CQTest` and `CQTestEnhancedInput` exist. | Epic API docs (primary); [disk] `EnhancedInputSubsystemInterface.h:148,195`, `Plugins/Tests/CQTestEnhancedInput` | **AD-12:** a deterministic in-game Scenario Runner that drives the real input pipeline with no OS focus. This replaces Win32 `SendInput` as the primary playtest gate (audit F-09). Win32 input stays as a secondary end-to-end smoke check. |
| R7 | **Gauntlet** runs Unreal sessions and checks the results. 5.7.1 changed test-tag handling (forum report). | Epic docs (primary); forum *(secondary)* | Gauntlet is not adopted. The scenario runner plus `UnrealToolchain` covers the need with less surface. Revisit in P10 for multi-process (multiplayer) runs. |
| R8 | **Unreal Insights** has built-in CLI exporters (`-OpenTraceFile … -NoUI -AutoQuit -ExecOnAnalysisCompleteCmd=…`). Paths with spaces need a `.rsp` file. 5.7 may duplicate "Frame" timer IDs *(secondary)*. | Epic KB "Automated trace analysis and CSV export" (primary) | P10 profiling: `-csvprofile` on **Test**-configuration builds (the CSV profiler and logs are off in Shipping), plus Insights export through a response file. Keep projects in paths without spaces. |
| R9 | Packaged size: a blank UE5 **Shipping** build is about 321 MB uncompressed (UE 5.3). Development adds more than 300 MB. The prerequisites installer adds about 48 MB. | Secondary (multiple) | **AD-19:** QA runs on Development or Test packages. Release packages are Shipping with trimmed plugins and compressed paks. Target ≤ 400 MB for a small generated game. |

## 2. LLM agents that build games: state of the art (2026)

| # | Finding | Source | Consequence |
|---|---|---|---|
| R10 | **Spec2Game** (Oct 2026, Pygame): a detailed, structured spec raised the mean overall score from 50.59 to 68.62. The spec has seven sections: *Overview; Scene & Interface; Objects & States; Player Interaction; Core Rules & Mechanics; Game Flow & Progression; Goal, Feedback & Termination*. Models do well at **game elements (80.8)** and badly at **rules/mechanisms (45.7)** and **goals/termination (44.1)**. Dynamic feedback (32.1) and visual actionability (40.7) are also low. "Executability isn't enough": 87 of 387 projects that passed every execution check still scored under 60. | arXiv 2610.04253 (primary) | **AD-9:** the Game Design Spec (GDS) uses those seven sections plus GameForge sections (art, audio, tech, acceptance). Rules and termination are typed data, not prose: event-condition-action rules and termination expressions, executed by a tested runtime engine (P5). Feedback is a first-class GDS section, compiled to VFX/SFX/UI on events. |
| R11 | **GameCraft-Bench** (Jun 2026, Godot, 140 tasks): the best agent (Claude Code, Opus 4.7) scores 41.5 %. Each submission must include **replayable input traces**, which the verifier replays under a fixed headless launch. Failure modes: recognisable mechanics that never assemble into a complete game, weak content depth and presentation, placeholder shapes. More tool calls does not mean a better score (r ≈ 0.02). | arXiv 2606.17861 (primary) | **AD-12:** each GDS goal and termination condition compiles to a replayable scenario, run headless against the packaged build. A "no placeholder" presentation rubric becomes a gate in P7. Budgets per step instead of open-ended agent loops. |
| R12 | CEGame-Bench (long-horizon, five engines, design document → game, play-based acceptance). "GUI Agents for Continual Game Generation": a play-to-code loop reached a 66.8 % rubric pass rate. | arXiv 2610.26098, benchmarklist (primary/secondary) | P8: iterate on change requests with play-based verification after every change. |

## 3. Local inference and AMD hardware

| # | Finding | Source | Consequence |
|---|---|---|---|
| R13 | **AMD HIP SDK 7.2 for Windows lists the RX 7700 XT (gfx1101) as supported** for runtime and HIP SDK. Community projects report official PyTorch-on-ROCm Windows wheels for gfx1100/gfx1101. | rocm.docs.amd.com system requirements (primary); GitHub community (secondary) | The "neural is impossible on this host" verdict is out of date (audit F-21). P9 adds a **gated spike**: install only with user approval, on `E:`, with a measured VRAM ceiling. |
| R14 | **Hunyuan3D-2.1 runs natively on Windows + ROCm 7.2** in pure-PyTorch mode: shape generation verified, texturing at 256 px. **TRELLIS.2** has a Linux RDNA3 guide (7900 XTX, 24 GB) and unverified Windows installers. On a gfx1151 benchmark both passed 9/9 images at 40k faces. | GitHub hunyuan3d-2.1-intel, trellis-2-rocm-comfyui, hawkymisc benchmark (secondary) | First neural candidate for **props** (not characters): Hunyuan3D-2.1 shape only, then remesh and UV in-engine with Geometry Script, then GameForge materials. Licence: the Tencent Hunyuan community licence has territory limits, which the existing `LicenseRegistry` must enforce. |
| R15 | Ollama and Qwen3.5: there were tool-call template bugs for Qwen3.5 in early 2026 (fixed by v0.17.6 per community reports). Thinking control is inconsistent across runtimes. | GitHub ollama#14493 (primary issue); secondary posts | Keep the **startup native-tool self-test per model** (exists). Always send `"think": false`. Validate every structured output with pydantic, with one bounded repair round and then fail closed. Record the Ollama version in run evidence. |

## 4. Desktop packaging

| # | Finding | Source | Consequence |
|---|---|---|---|
| R16 | Qt for Python documents **Nuitka** as a supported deployment path (`--standalone --plugin-enable=pyside6`; onefile needs `zstandard`). It produces smaller executables than PyInstaller and builds more slowly. No confirmation was found for PyInstaller with Python 3.14 + PySide6 6.12. | doc.qt.io/qtforpython-6 (primary) | **P11:** package the IDE with Nuitka standalone (installing it needs approval). Fall back to PyInstaller only if a measured build passes the smoke test. Never bundle model weights. |

## 5. Decisions this research does *not* support

- **Rewriting the IDE in QML or a web stack.** The widget IDE meets its resource budgets, and the gap is information
  architecture, not the toolkit (P4).
- **Adopting Epic's cloud AI Assistant or any MCP server as the mutation path.** No auth, needs an Epic login, and
  calls are serial on the game thread.
- **Moving to UE 5.8 now.** Every piece of evidence is on 5.7.4, and the only 5.8 feature that matters (MCP) is
  experimental. Revisit at P10 with a compatibility lane.
- **Mover-based locomotion.** Experimental in 5.7.
