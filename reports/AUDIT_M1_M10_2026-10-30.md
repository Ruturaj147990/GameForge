## 2. Defects found and fixed

### M1 — Planner (`src/gameforge_ide/backend/agent/plan_executor.py`)
1. **Approval bypass.** Every tool was dispatched with `approval_granted=True`, so a task without `requires_approval` could run `create_game`, `run_command` or a mutating `unreal_editor` call unapproved. Tasks now inherit the tool's requirement (`ToolGateway.tool_requires_approval`).
2. **False completion.** `TIMEOUT`, `NO_RECIPE`, `PENDING_APPROVAL`, `ENGINE_UNAVAILABLE`, `STALE` and non-zero exit codes counted as success. They now fail closed (`FAILURE_STATUSES`, `_step_failure`).
3. **A rejected approval hung the plan forever.** The task is now `CANCELLED` and its descendants `BLOCKED`.
4. **One pending approval stopped independent branches.** Other ready branches now keep running.
5. **Resume deadlocked on `READY`/`REPAIRING`.** Both are now reconciled.
6. **The IDE's Run/Resume/Cancel buttons did nothing** (signals had no listeners). They now drive `desktop/services/plan_runner.py`. Plan-task approvals carry `plan_id`, so approving one releases the task instead of running the tool outside the plan.
7. Note: the docstring claims read-only tasks run concurrently; execution is in fact serial. This is safe, but the docstring overstates it.

### M2 — Blueprint graph (`GameForgeBlueprintGraphLibrary.cpp`)
- `blueprint_compile` now returns the real `FCompilerResultsLog` messages (severity and text, error/warning counts) instead of just "BS_Error".
- `blueprint_connect_pins` returns the schema's rejection reason. The redundant reverse attempt was removed.

### M3 — UMG (`GameForgeWidgetLibrary.cpp`)
- **Root cause of broken layouts.** The canvas slot read `position`/`size`/`anchors`/`alignment` as JSON objects, but every caller passes arrays. The values silently became 0, giving top-left anchors and a 0×0 size, while the op still returned `configured: true`. Both forms are now accepted, bad shapes fail, and the slot is read back.
- `take_high_res_screenshot` renders the camera only, so no M3/M4 screenshot had ever shown a widget. Added `CaptureViewportWithUI` (`viewport_screenshot` with `show_ui`, and `LiveEditorLink.capture_screenshot(show_ui=True)`).

### M4 — Functional UMG + gameplay state
- **Fake click.** `TriggerButtonClickRealInput` sent pointer events with no mouse button (which `SButton` ignores), then ran HealBoost/ToggleHUD/CloseMenu itself based on the button's *name*, rewrote the HUD, and always reported `clicked: true`. It now hit-tests through the host window's hit-test grid, routes a real LMB press/release, and counts genuine `OnClicked` broadcasts with a probe. It fails unless exactly one fires, and never touches gameplay state.
- **Fake event-driven HUD.** `gameplay_modify_state` wrote HealthBar/HealthLabel directly. The component now refreshes the HUD from its own change events (`RefreshViewportHUD`).
- **Bindings.** `widget_bind_event` supports `GameplayAction`, which builds a real event-graph call to `UGameForgeGameplayStateComponent::ExecuteMenuActionInWorld`. Re-binding now replaces the previous action instead of stacking a second exec link (which would double-fire).
- **Editor-only component.** Unreal refused to compile the bound graph: *"Cannot use the editor function … in this runtime Blueprint"*. Added a **`GameForgeRuntime`** plugin module that holds the component; `GameForgeEditor` depends on it. This also makes the component usable in packaged games (not yet exercised there).

### M5–M7 — Recipes (`src/gameforge_ide/recipes/*/templates.py`)
- **Platformer:** collectibles, checkpoints and the goal accepted *any* overlapping actor. They now require a player-controlled pawn.
- **Card battler (pre-existing, already in `f0d5121`):** the HUD used `State->TurnCount`, which doesn't exist, so the recipe **did not compile**. The "hardened" `GFCardBattler.exe` (Oct 28 01:00) predates the hardened source (Oct 29 21:12).
- **Card battler:** the player had **no input path**. The End Turn and Restart UMG buttons were unbound, the footer advertised keys that weren't bound, and nothing called `PlayPlayerCard`. Added Canvas hitboxes (click a card, then a lane), bound keys (1/2/3, Tab, Enter/Space, E, R), and wired the UMG buttons.
- **Card battler fairness:** the rules engine never tracked opponent energy; only the AI's local counter limited it. `OpponentEnergy` is now enforced by `CanPlayCard`/`PlayCard`, with an automation test added.
- **All four playable recipes** log `GF_EVENT` markers at real transitions (moved, jump, collect, checkpoint, respawn, attack, damage, card_play, turn_end, reset, landmark_discovered).

### M4–M7 hardening — Real input (`src/gameforge_ide/unreal/real_input.py`, `scripts/verify_real_input_packaged.py`)
- `-log` opened a **console window** in the game's process. The verifier picked that window and focused it, so W/SPACE/R were typed into the log console. Earlier "1280x480 client" geometry was the console.
- `focus_window` returned `True` unconditionally. It now reports whether the exact window is foreground, and every input method refuses (`NotForegroundError`) rather than send keystrokes into another application.
- The verifier set `ok=True` once input was dispatched. Each step now needs its expected `GF_EVENT` in the game's own log (`-abslog`, `-forcelogflush`).
- The packaged `.exe` is a launcher that spawns the real binary and survived `terminate()`. **11 leaked game processes (~8.5 GB) were closed.** The verifier now launches the real binary and kills the process tree.

### M8 — Procedural world
- The procedural character never bound **Restart (R)**, so the M8 "R reset" input did nothing. Added `RequestWorldReset`.

### M9 — Character (`backend/tools/character_generator.py`, `scripts/verify_character_creation.py`)
- **Fabricated evidence.** The M9 script imported `Engine/Content/FbxEditorAutomation/AnimatedCharacter.fbx` and reported it as the generated character. That is why Unreal showed 18 bones (`Hips1, HipLeft, …`, 11 materials) against the generator's 20 joints (`root, pelvis, …`). The "broken asset rejected" check pointed at a nonexistent file.
- **glTF exporter defects:** no joint hierarchy (every joint a scene root), absolute instead of parent-relative joint translations, no inverse bind matrices, centimetres written as metres, and Z-up written into Y-up glTF. All are fixed and covered by a unit test.
- The import op now uses Interchange for glTF (FBX options were being applied to glTF). The M9 script now imports the generated file.

### M10 — Animation
- The synthesized clips never reached Unreal. The "retargeted" sequence was `AnimatedCharacter.fbx`'s own animation, copied with `SetSkeleton` (not a retarget). `CreateLocomotionAnimBlueprint` builds an **empty** AnimBP: no AnimGraph, no state machine.
- Added `ImportMotionClip` (C++, `IAnimationDataController`) and `anim_sample_bone_pose`. `verify_animation_pipeline.py` is marked superseded for in-engine evidence.

### Shutdown policy (user direction, D-062)
- Removed `SystemShutdownManager`, the `request_/cancel_system_shutdown` gateway tools, the terminal shutdown special-case, `.gameforge/power`, and the host-profile keys. Docs now say: when the user says "shut down the PC", run `shutdown /s /t 0`.
- Also fixed: the host profile was invalid JSON (unescaped `E:\` paths), and `DECISION_LOG.csv` had no trailing newline.
