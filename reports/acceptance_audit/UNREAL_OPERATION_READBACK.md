# GameForge — Unreal Operation & Read-Back Discrepancy Investigation

**Audit Date:** 2026-11-03T14:10:00Z  
**Investigator:** Antigravity Autonomous Inspector & Remediation Agent  
**Status:** COMPLETE & VERIFIED  

---

## 1. Executive Summary

This report delivers the root-cause analysis and verified findings for the four suspicious runtime behaviors reported in the Unreal execution logs during Snake and Ladders generation:
1. **Actor Transform Discrepancy:** `GameForgeGridBoard` logged as placed at `(340, 710, 430)` but read-back reported `(0, 0, 50)`.
2. **Duplicate PlayerStart Spawning:** `PlayerStart` actor spawning appeared multiple times in succession.
3. **Map Load-Before-Exists Warning:** Map loading attempted before `Level_1.umap` was created on disk.
4. **Harmless Source Control Checkout Warning:** Log reports unsuccessful checkout while assets are successfully saved.

---

## 2. Technical Findings & Root Causes

### 2.1 Actor Transform Discrepancy: `(340, 710, 430)` vs `(0, 0, 50)`
- **Mechanism:**
  - In `src/gameforge_ide/composer/layouts/board.py`, the layout placed the primary board actor at:
    ```python
    PlacedActor(
        actor_id="board_0",
        entity_id="board",
        runtime_class="/Script/GameForgeRuntime.GameForgeGridBoard",
        location=(0.0, 0.0, 50.0),
        ...
    )
    ```
  - In `src/gameforge_ide/composer/compose.py` (lines 120-150), `compose()` checks `unplaced = [e for e in gds.entities if e.entity_id not in already_placed_entities]`.
  - When the GDS entity ID generated by `expand.py` was `"boards"` (plural) while `layout_plan.actors` declared `entity_id="board"` (singular), the GDS board was marked as *unplaced*.
  - `compose.py` then ran Poisson disk scatter on all unplaced entities, calculating a random 2D free-point `(340.0, 710.0, 430.0)` and logging `"Adding actor boards at (340, 710, 430)"`.
  - However, in the actual level ops dispatch to Unreal, `board_0` was executed first at `(0, 0, 50)`, and the Unreal read-back queried `actor.get_actor_location()`, truthfully returning `(0, 0, 50)`.
- **Resolution:**
  - Updated `layouts/board.py` to match the GDS board entity ID (`e.entity_id`) and propagate all GDS properties (`board_size`, `cell_size_cm`, `snakes`, `ladders`).
  - Added strict deduplication in `compose.py` so entities matching `kind == EntityKind.BOARD` are never scattered twice.

### 2.2 Duplicate PlayerStart Spawning
- **Mechanism:**
  - In `src/gameforge_ide/composer/level_ops.py` (lines 46-55), step 1b unconditionally emitted:
    ```python
    emit("spawn_actor", {"actor_class": "PlayerStart", "label": "GF_PlayerStart", ...})
    ```
  - Later in step 4 (lines 70-77), `level_ops.py` iterated through `plan.actors`.
  - When layouts (like `tactical_fps` or custom layouts) also added a `PlayerStart` actor or when player character entities had `placement.slot == "player_start"`, a second `PlayerStart` was emitted under label `player_0` or `GF_PlayerStart_2`.
- **Resolution:**
  - Added duplicate detection in `level_ops.py`: if `plan.actors` already contains an actor of class `PlayerStart` or label `GF_PlayerStart`, the automatic step 1b emission is skipped.

### 2.3 Map Loading Order of Operations
- **Mechanism:**
  - The pipeline assembly handler in `legacy_assemble()` dispatched `load_level` to set the active editor context before verifying whether `Level_1.umap` existed on disk.
  - In a fresh build, the map does not exist until `new_level` and `save_all` have run.
- **Resolution:**
  - Fixed assembly sequence to ensure `new_level` is always the first operation executed, and `save_all` commits the package to `/Game/Maps/Level_1.umap` before any other module attempts to load or query the map asset.

### 2.4 Source Control Checkout Warning Analysis
- **Mechanism:**
  - The log snippet contained:
    ```text
    LogSourceControl: Warning: Check out of /Game/Maps/Level_1 was unsuccessful.
    LogSavePackage: Moving '.../Saved/Level_1.tmp' to '.../Content/Maps/Level_1.umap'
    LogSavePackage: Saved package: E:/GameForge/projects/SnakeAndLadders/Content/Maps/Level_1.umap
    ```
  - Unreal Engine's `EditorLoadingAndSavingUtils` automatically invokes `ISourceControlModule::Get().GetProvider().Execute(ISourceControlOperation::Create<FCheckOut>(), ...)` whenever an asset package is saved.
  - When no Perforce or Git server is configured in the Unreal Editor session (or when the file is untracked), the provider returns failure and emits a standard warning.
  - Unreal's save system handles this non-fatal response gracefully by writing to a temporary file (`.tmp`) and atomically moving it to the destination `.umap` file.
- **Classification:**
  - **Verdict:** `[HARMFUL=FALSE] [BENIGN_ENGINE_LOG]`.
  - The warning does not indicate file corruption, permission denial, or failed persistence. The asset was verified present, readable, and intact on disk.

## 3. Read-Back Validation Enforcement

- Upgraded `level.py` and `level_ops.py` to assert that every `spawn_actor` operation verifies its position against requested coordinates within a 1.0 cm tolerance. Any discrepancy triggers an explicit validation warning.
