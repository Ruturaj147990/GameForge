In Unity 6 (Entities 1.3), the entity authoring and baking pipeline has shifted from the legacy `GameObjectConversionSystem` (which relied on `IComponentData` and `IComponentDataAuthoring` or `IComponentDataAuthoring` interfaces) to a more explicit, type-safe `Baker<T>` pattern. This change improves performance, reduces reflection overhead, and provides better compile-time safety.

### Key Changes:

1. **Deprecation of `GameObjectConversionSystem`**:
   - In Unity 2022.3 (Entities 1.0), you would use `GameObjectConversionSystem` to convert GameObjects into entities. This system relied on `IComponentData` and `IComponentDataAuthoring` interfaces.
   - In Unity 6 (Entities 1.3), `GameObjectConversionSystem` is deprecated. Instead, you use `Baker<T>` to define how a GameObject (or its components) should be converted into an entity.

2. **`TransformUsageFlags` Replaces Legacy Authoring Flags**:
   - In Unity 2022.3, you would use `TransformUsageFlags` (e.g., `TransformUsageFlags.Dynamic`) to specify how the transform should be handled during baking.
   - In Unity 6, `TransformUsageFlags` is still used, but it is now more tightly integrated with the `Baker<T>` pattern. The flags are passed directly to the `Baker` constructor or used within the `Bake` method.

3. **Correct Unity 6 `Baker<T>` Syntax**:
   - `Baker<T>` is a generic class where `T` is the type of the GameObject component you are baking.
   - You override the `Bake` method to define how the component data should be converted into entity components.
   - You use `AddComponent` to add components to the entity.

### Example: Baking a Custom Component

```csharp

using UnityEngine;

public class MyComponent : MonoBehaviour
{
    public float value;
}

{
    public MyComponent component;

    public void OnBake(Unity.Entities.Entity entity, Unity.Entities.EntityManager entityManager)
    {
        entityManager.AddComponentData(entity, new MyComponentData { value = component.value });
